# 업무 발견·실행·재사용 경험 개선 — 2026-09-03

기준 커밋은 `93a73e9`이다. 이 커밋은 사용자의 명시적 승인 후 `wilcoco/nvidia`의 `main`에 푸시했다. 아래 후속 변경도 사용자의 추가 푸시 요청에 따라 `main`에 반영하는 개선 묶음이다. 운영 배포 완료 여부는 별도 확인이 필요하다.

## 제품의 기준

업무 현황 한 조각에서 출발해 에이전트가 앞뒤의 업무, 담당자, 판단 기준과 예외를 질문한다. 사람의 답과 교정으로 실행 가능한 플레이북을 만든다. 담당자가 순서대로 실행하고, 비슷한 업무에는 관련 플레이북을 제안해 사용자가 선택한다. 실행에서 발견한 개선점은 사람이 검토한 새 버전으로 남긴다.

측정값 검증·재작업·승인은 이 흐름의 실행 가능성을 보여주는 사례다. 제품 전체를 승인 도구로 설명하지 않는다. 데스크톱의 왼쪽 업무와 오른쪽 프로세스 그래픽이 기본 경험이다.

## 바뀐 사용 흐름

- 첫 방문: `describe_workspace`에 쉬운 서비스 설명, 생성/실행/재사용/개정 안내, 현재 로그인·초안·실행 상태를 추가했다. “이게 뭐야? 어떻게 써?”에는 방문자의 언어로 설명하고 다음 행동 하나를 제시한다. 소개 질문은 자료나 실행을 변경하지 않는다.
- 새로 만들기: 첫 화면에 업무 입력을 바로 보여주고 `Create a new playbook`을 명시했다. 업무를 저장한 뒤 생성 의도를 `playbookRequest`와 활동 기록으로 WebMCP에 전달한다. 에이전트가 질문하고, 답으로 초안을 만들고, 사람이 교정·확인해 저장한다.
- 재사용: 입력 중 관련 플레이북과 추천 이유가 보인다. 조건과 단계를 미리 본 뒤 사용자가 선택하면 별도의 실행이 열린다. 유형을 아직 정하지 않은 자유 입력에서도 키워드 후보를 보여주되 적합성 확인을 요청한다.
- 그래픽: 로그인한 데스크톱에서는 오른쪽 패널을 기본으로 연다. 새 초안·개정 초안·질문·행동 승인 요청도 접힌 패널을 연다. 기존 그래픽, 직접 편집, 진행 표시를 유지한다.
- 실행: 시작 후 My tasks로 이동한다. 필요한 입력, 다음 담당자, 판정 대기, 승인 요청이 현재 상태에 맞게 표시된다. 완료 후에는 개선 사항을 새 버전으로 남기는 방법을 안내한다.
- 초기에 적용했던 패널 기본 접기와 `Save & invite` 문구는 사용자 피드백에 따라 위 동작으로 수정했다.

| 상태 변경 이벤트가 이전 데이터를 읽음 | 스토어를 먼저 갱신한 뒤 이벤트 발행 |
| 늦은 증빙 저장이 다른 실행을 가리킬 가능성 | 요청 시점의 맵·실행을 고정하고 변경 시 중단 |
| 긴 요청·UI 오류가 숨겨짐 | API 제한 시간, 중복 실행 잠금, 오류 표시와 입력 보존 |
| 삭제 HTTP 실패를 성공으로 표시 | DELETE 응답 상태 검사 후 실패 전달 |

| 키워드 추출에서 한국어 제거 | 유니코드 문자 유지; 한국어 재사용 후보 회귀 검증 |
| 관련성 점수가 확률처럼 보임 | 추천 근거와 적합성 확인 안내로 변경 |
| 첫 화면의 상태·설정 표시 과밀 | 시작 화면 분리, 실행 안내를 인라인 표시, 설정 메뉴 정리 |

## 검증 결과

- TypeScript 검사와 production 빌드 통과, `git diff --check` 통과.
- SDK 13개, 메모리/PostgreSQL 통합 4개, 스토어 2개: 총 **19개 테스트 통과**. 이후 생성 의도·버전 반환 변경에 해당하는 SDK/스토어 15개를 다시 통과했고 최종 패널 변경 후 타입 검사·빌드를 통과했다.
- 실제 브라우저의 WebMCP 호출로 로그인 전 소개와 명시적 새 플레이북 생성 요청을 확인했다. 모든 외부 에이전트가 같은 답변을 생성한다는 보장은 검증 범위에 포함하지 않는다.
- 로컬 메모리 서버의 `QA guided staging release`: 질문 답변 → 사람의 단계 이름 교정 → 저장 → 값 12 제출 → 0 기준 승인 분기 거부 → Operations 재작업 → 새 측정 0 → Reviewer 승인 → 새로고침 후 완료 복원.
- 다른 업무 문장에서 관련 플레이북 추천·단계 미리보기·선택을 확인했다. 새 실행은 빈 입력으로 시작했고 별도 측정·승인으로 완료됐다.
- 완료 후 `Propose changes`로 규칙 설명을 보강해 v2로 저장했다. 개정판의 단계는 모두 미완료로 초기화되고 새 실행을 기다렸다. 저장 직후 버전 표시 누락을 발견해 수정하고 스토어 회귀 테스트로 확인했다.
- 로컬 `QA 금형 시사출과 양산 투입`: 한국어 업무 입력 → 새 플레이북 요청 → 한 단계 그래픽 → 앞뒤 업무 질문 → 검증용 답변 → 세 단계와 담당자로 확장 → 라이브러리 저장. 검증용 답변이며 실제 현업 인터뷰나 도입 성과가 아니다.
- 데스크톱 미리보기에서 업무·그래픽 병행을 확인했다. 작은 화면은 가로 넘침을 잠깐 점검한 뒤 기본 화면 크기로 복원했다.
