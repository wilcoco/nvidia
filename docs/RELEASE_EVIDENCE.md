# Release evidence and Devpost checklist

Generate the final manifest only from a clean, pushed commit after Railway has
deployed it. The command builds the exact commit, fetches fresh LIVE assets,
requires byte-identical `index.html`, app bundle and SDK, and refuses a missing
or mismatched build marker.

```bash
mkdir -p qa-evidence/releases
RUN_ID=53 \
REVIEW_ID=64 \
RUN_BUILD=c9716f9 \
VIDEO_BUILD=1a9140b \
VIDEO_URL=https://youtu.be/kKhdmuNePNM \
VALIDATION_SUMMARY='check PASS; base 70/70; strict Chrome 1/1' \
npm run --silent release:manifest > qa-evidence/releases/$(git rev-parse --short=7 HEAD)-manifest.md
```

`RUN_BUILD` must be an exact lowercase hexadecimal Git SHA in either the
seven-character display form or the full forty-character form. Shorter
prefixes and non-hex labels are rejected before the build or network checks.
It is deliberately separate from the release commit. A run from an older build
remains useful history but is shown as a mismatch, never silently promoted to
evidence for the current release. Perform a new qualification run or explicitly
document that the intervening commit changes evidence tooling or documentation
only.

Before submitting:

- [ ] `HEAD`, `origin/main`, the on-screen build after hard reload and manifest commit agree.
- [ ] The three live artifact hashes were generated by the manifest command.
- [ ] The run and review ids exist and their `RUN_BUILD` is recorded.
- [ ] The public video URL works and its recorded build is stated.
- [ ] `npm run check`, `npm test` and strict Chrome results have exact counts.
- [ ] PostgreSQL is claimed only from the required CI lane or dated local PG evidence.
- [ ] External WebMCP and physical mobile are claimed only from their evidence folders.
- [ ] Devpost fields, repository URL and public video were opened once in a logged-out/private context.
