# 리뷰 요청과 증거 표시 수정 — 2026-09-03

## 확인한 원인

1. 서버의 승인 선행 조건에 `request_review` 작업 자체가 포함되어 있었다. 해당 작업은 리뷰 생성 성공 후에 완료되므로, 명시적인 WebMCP 요청이 자기 자신을 미완료 업무로 판단해 거절됐다.
2. 리뷰의 동시성 검증은 실행 데이터를 사용했지만 화면은 원본 업무 일지의 `data`를 읽었다. 따라서 일지에 `0/true`, 이후 담당자 입력에 `12/false`가 있는 경우 화면과 실제 검증 대상이 달랐다. 취소된 리뷰도 같은 업무 일지를 참조하여 과거 증거가 바뀔 수 있었다.

## 변경

- 리뷰 생성 시에만 현재 `request_review` 행정 작업을 선행 조건에서 제외한다. 실제 미완료 업무, 필수 입력, 분기 조건, 잘못 지정한 승인 단계는 계속 막는다. 최종 승인은 완료된 요청과 실제 선행 업무를 다시 검사한다.
- 클라이언트는 최신 실행 상태를 저장한 뒤 리뷰를 요청하고, 성공한 요청 단계도 저장한 뒤 담당자에게 넘긴다. 다른 실행에 속한 요청으로 현재 실행을 진행시키지 않는다.
- 서버가 리뷰 생성 시 `review_evidence` 스냅샷을 저장한다. 해당 승인 범위의 담당자 입력이 원본 일지의 값보다 우선하며, 입력하지 않은 필드에 원본 기본값을 다시 채우지 않는다. 이전 verification 메타데이터는 현재 실측의 통과 증거로 표시하지 않는다.
- PostgreSQL은 실행 행을 먼저 잠그고, 동일한 트랜잭션에서 선행 조건·증거·fingerprint를 확정한다. 최종 승인도 잠금 안에서 선행 조건을 재검사한다.
- 리뷰 화면과 과거 리뷰 내역은 각 리뷰의 스냅샷을 표시한다. 원본 업무 일지는 보존한다.
- 스냅샷이 없는 기존 실행 리뷰에는 안내를 표시하고 승인을 막는다. 기존 행을 자동 승인·삭제·재작성하거나 과거 증거를 추정하여 채우지 않는다. 필요한 경우 사용자가 사유를 남겨 반려한 뒤 새 리뷰를 요청할 수 있다.
- 업무가 다시 열리면 남아 있던 “리뷰 요청 완료·승인 대기” 안내를 지운다.

## 검증 결과

- 변경 전 회귀 테스트에서 자기 참조 `process_incomplete`와 `12/false` 스냅샷 누락을 각각 재현했다.
- 메모리·PostgreSQL을 포함한 전체 테스트 48개 통과. 이후 추가한 대기 안내 회귀와 기존 리뷰 호환성 검증을 포함하여 storage/store 테스트 16개도 통과했다.
- 타입 검사, 프로덕션 빌드, diff 공백 검사 통과.
- 실제 브라우저와 WebMCP로 별도 로컬 서버 `localhost:18996`에서 확인했다.
  - 실측 전 `request_review`는 실제 선행 업무 미완료로 거절됐다.
  - 담당자가 `12/false`를 입력한 후 같은 WebMCP 요청은 성공했다. `force`를 사용하지 않았다.
  - Lee의 Reviews에 `rowCountDelta: 12`, `verificationQueriesPassed: false`가 표시됐다. 원본 일지 `0/true`는 그대로였다.
  - 재작업 후 화면의 완료 버튼으로 만든 새 리뷰에는 `0/true`, 취소된 이전 리뷰에는 `12/false`가 따로 표시됐다. 브라우저에서 이 리뷰들을 최종 승인하지 않았다.

검증은 전용 로컬 서버와 별도 로컬 PostgreSQL 데이터베이스에서 실행했다. 사용자가 라이브에 증거로 남긴 리뷰와 실행은 조회·변경·승인하지 않았다. 이 문서는 로컬 수정 검증이며 라이브 배포 완료를 뜻하지 않는다.
